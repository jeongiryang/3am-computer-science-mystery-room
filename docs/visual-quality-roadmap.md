# 비주얼 품질 로드맵

## 1. 현재 비주얼 상태 진단

Room55516은 1차와 2차 비주얼 패스를 거치며 이전보다 개선됨. 바닥 타일, 벽면, 조명, 모니터 빛, 주요 오브젝트 실루엣이 추가되어 블록아웃 단계보다는 공간성이 분명해짐. 다만 아직 고퀄리티 게임 화면으로 보기에는 부족함.

진단 항목은 다음과 같음.

- 오브젝트가 여전히 도형 조합처럼 보임.
- 질감이 부족해 금속, 종이, 플라스틱, 타일, 유리의 재질 차이가 약함.
- 플레이어가 파란 네모라 몰입감이 낮음.
- 배경, 오브젝트, 조명 밀도가 아직 균일하지 않음.
- 공간은 넓지만 세부 장식과 재질감이 부족함.
- UI는 개선됐지만 방 비주얼과 완전히 같은 퀄리티 기준에 있지는 않음.
- 외부 에셋 없이 Godot 기본 도형만으로는 고퀄리티 표현에 한계가 있음.

현재 도형 기반 화면은 플레이 가능한 구조 확인에는 적합하지만, 최종 공개용 비주얼로 사용하기에는 완성도가 부족함. 앞으로 다른 room에 같은 수준을 반복 적용하기보다, Room55516에서 에셋 기반 기준선을 먼저 확정해야 함.

## 2. 목표 비주얼 품질

최종 목표는 2D 탑다운 미스터리 탐험 게임에 어울리는 통일된 화면 품질임.

- 2D 탑다운 미스터리 탐험 게임으로 인식됨.
- 새벽 3시 공과대학의 차갑고 정적인 분위기를 전달함.
- 반실사풍에 가까운 저채도 2D 스타일 또는 고정된 벡터/픽셀 스타일 중 하나로 통일함.
- 배경, 오브젝트, UI, 사운드가 같은 톤을 공유함.
- 한눈에 학교, 공과대학, 실습실, 복도, 서버실로 인식 가능함.
- 라벨 없이도 주요 오브젝트를 알아볼 수 있음.
- 조명과 질감으로 분위기가 전달됨.

비주얼 기준선은 "임시 도형을 많이 배치한 화면"이 아니라 "실제 에셋을 적용한 작은 완성 장면"을 기준으로 잡아야 함. Room55516은 그 기준선을 검증하는 첫 공간으로 사용함.

## 3. 도형 기반 비주얼의 역할 재정의

도형 기반 비주얼은 최종 에셋이 아님. 앞으로는 다음 용도로 유지함.

- 레이아웃 검증
- 충돌/동선 검증
- 오브젝트 위치 확정
- 퍼즐/이벤트 흐름 검증
- 최종 에셋 적용 전 블록아웃

즉, ColorRect, Polygon2D, Line2D 기반 표현은 "어디에 무엇이 있어야 하는지"를 정하는 작업에는 유용하지만, 최종 몰입감과 포트폴리오 품질을 책임지는 단계로 보지는 않음.

## 4. 에셋 기반 전환 전략

### 선택지 비교

| 선택지 | 장점 | 단점 | 현재 프로젝트 적합도 |
| --- | --- | --- | --- |
| 무료 CC0/상업 사용 가능 에셋 활용 | 빠르게 품질을 올릴 수 있음. 라이선스가 명확하면 배포 부담이 적음 | 스타일이 섞이기 쉬움. 공과대학/실습실에 맞는 에셋을 찾기 어려울 수 있음 | 중간 |
| AI 생성 이미지 기반 자체 에셋 제작 | 원하는 분위기와 소재를 빠르게 시도 가능함. Room별 콘셉트 초안 제작에 유리함 | 스타일 일관성, 후처리, 라이선스/사용 범위 기록이 필요함 | 보조 수단으로 적합 |
| 직접 제작한 단순 픽셀/벡터 에셋 | 스타일 통일이 쉬움. 작은 프로젝트에 맞게 제어 가능함 | 제작 시간이 오래 걸림. 미술 완성도 확보가 필요함 | 높음 |
| Godot 도형 기반 유지 후 제한적 개선 | 구현 비용이 낮고 현재 구조를 유지하기 쉬움 | 고퀄리티 체감이 낮음. 최종 공개용 화면으로는 한계가 큼 | 낮음 |

### 추천 전략

- 외부 라이선스가 명확한 에셋 또는 직접 생성/제작한 에셋만 사용함.
- 모든 에셋은 동일한 해상도, 색감, 명암, 질감 기준을 따름.
- Room55516부터 대표 에셋 세트를 먼저 적용함.
- Room55516 기준이 확정되면 Hallway5F, DepartmentOffice, Room55110, Lobby, ServerRoom으로 확장함.
- 외부 에셋은 `docs/asset-credits.md`에 출처와 라이선스를 기록함.
- AI 생성 이미지를 사용할 경우 생성 도구, 생성 목적, 사용 위치, 후처리 여부를 기록함.

## 6. 에셋 규격 제안

- 기준 시점: 2D top-down
- 기본 타일 크기 후보: 32x32 또는 64x64
- 주요 오브젝트 크기 기준:
  - Player: 타일 1개 안에서 읽히는 크기
  - 책상/컴퓨터: 2~3타일 폭
  - 칠판/문/사물함: 벽면에 붙는 대형 오브젝트
  - 서버랙/보안 게이트: 공간의 목적을 보여주는 대형 오브젝트
- 파일 포맷 후보: PNG 우선
- 투명 배경 사용
- 색상 팔레트 제한
- 같은 광원 방향 유지
- 같은 해상도 밀도 유지
- UI 에셋과 게임 오브젝트 에셋은 톤을 공유하되 역할은 구분함.
  - UI: 더 선명한 텍스트 대비와 얇은 청록 포인트 사용
  - 오브젝트: 저채도 재질감과 공간 조명 반사 중심

## 7. 에셋 적용 우선순위

고퀄리티 체감이 큰 순서는 다음과 같음.

1. Player sprite
2. Room55516 floor/wall
3. Computer/blackboard/desk/locker/door
4. 조명과 그림자 overlay
5. DialogueBox/PasswordInput 세부 polish
6. Hallway5F 배경과 문/CCTV/비상등
7. DepartmentOffice/55110/ServerRoom 확장

Player가 파란 네모로 남아 있으면 전체 화면의 임시 느낌이 강하게 남음. 따라서 Room55516 배경보다 먼저 또는 동시에 Player sprite 초안을 적용하는 것이 효율적임.

## 8. 사운드와 비주얼의 관계

사운드는 비주얼의 부족한 정보량을 보완하고, 같은 화면이라도 더 완성된 공간처럼 느끼게 만듦.

- 기본 앰비언스가 비주얼 분위기를 보강함.
- BGM은 계속 크게 깔기보다 공간별 앰비언스와 이벤트 사운드 중심으로 사용함.
- Hallway5F는 야간 순찰자 이벤트를 고려해 발소리, 형광등, 문소리 여지를 남김.
- 점프스케어는 나중에 별도 이벤트 시스템 후 구현함.
- UI 효과음은 짧고 절제된 보안 패널/시스템 톤으로 맞춤.

## 9. 야간 순찰자/NPC 이벤트 대비

추후 복도에 야간 순찰자 또는 C 교수 같은 가명 처리 NPC를 추가할 수 있음. 다만 공개 배포용 프로젝트에서는 실존 인물명이 직접 연상되지 않도록 설계해야 함.

- 실존 인물명 직접 사용은 공개 배포용으로 피함.
- 가명 또는 상징화된 NPC로 설계함.
- 초기에는 추격 AI가 아니라 기척, 실루엣, 발소리, 조명 변화부터 구현함.
- 잡혔을 때 점프스케어는 후속 단계로 분리함.
- NPC sprite가 필요할 경우 Player보다 어둡고 읽기 쉬운 실루엣 우선으로 제작함.
- Hallway5F 비주얼 패스에서는 NPC가 지나갈 수 있는 빈 공간, 조명 사각지대, 문 그림자를 남겨 둠.

## 11. Room55516 에셋 기반 전환 1차 기록

Room55516 에셋 기반 전환 1차에서는 외부 다운로드 없이 프로젝트 내부 자체 제작 SVG 초안을 사용함. Player sprite, floor/wall, 주요 조사 오브젝트, 형광등, 모니터 glow를 우선 적용해 도형 기반 블록아웃에서 실제 에셋 기반 화면으로 넘어가는 기준을 시험함.

이번 단계의 목적은 최종 비주얼 완성이 아니라 에셋 규격, 색감, scene 적용 방식, 기존 조사/비밀번호/엔딩 흐름과의 호환성을 확인하는 것임. 다음 단계에서는 Room55516 SVG 초안의 완성도를 높이거나 PNG/Sprite2D 기반 정식 에셋으로 교체하는 작업이 필요함.

## 12. Room55516 에셋 QA polish 기록

Room55516 에셋 QA 단계에서는 Player sprite의 실루엣, 바닥/벽 대비, 형광등/모니터 glow 강도, 주요 오브젝트 테두리와 청록 포인트를 조정함. 이 단계도 최종 에셋 완성이 아니라 SVG 기반 기준선 polish이며, Godot 에디터에서 실제 화면 크기와 가독성 수동 확인이 필요함.

## 13. Room55516 비주얼 오버홀 1차 기록

Room55516 비주얼 오버홀 1차에서는 Player를 4방향 SVG sprite로 분리하고, 이동 방향에 따라 바라보는 방향이 바뀌도록 구현함. Room55516 주요 오브젝트는 입체형 SVG 초안으로 다시 정리해 윗면, 측면, 그림자, 하이라이트가 보이도록 보강함.

이번 단계는 다른 room에 확산하기 전 Room55516 기준선을 높이는 작업임. 여전히 최종 상용 에셋 완성 단계는 아니며, Godot 에디터에서 실제 화면 기준의 크기, 대비, 가독성 확인이 필요함.
