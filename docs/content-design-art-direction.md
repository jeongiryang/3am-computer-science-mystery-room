# 콘텐츠 설계 및 아트 디렉션

## 1. 프로젝트 확장 목표

현재 MVP는 실습실 1개, 조사 오브젝트 5개, 비밀번호 입력, 엔딩 전환으로 구성된 짧은 탈출 흐름임. 확장 목표는 이 구조를 약 10분 분량의 2D 미스터리 탐험 게임으로 키우는 것임.

확장 방향은 방향 B로 설정함. 단순한 축소판 방탈출이 아니라 공과대학 내부를 여러 공간으로 나누고, 공간 이동과 단서 연결을 통해 플레이어가 사건을 추적하는 구조로 확장함.

게임의 핵심 경험은 다음과 같음.

- 새벽 3시 공과대학 안을 조용히 탐색함.
- 강의실, 복도, 과사무실, 1층 공간, 서버실을 이동하며 단서를 모음.
- 각 공간에서 짧은 상호작용과 이벤트를 경험함.
- 단서가 다른 공간의 잠금, 비밀번호, 접근 권한과 연결됨.
- 엔딩에서 이후 1인칭 공포 후속작으로 이어질 수 있는 세계관 상징을 남김.

이 문서는 실제 이미지, 사운드, 폰트 에셋을 추가하지 않음. 향후 제작 단계에서 필요한 스타일 기준과 에셋 목록을 정리하는 설계 문서임.

## 2. 아트 디렉션

전체 비주얼 콘셉트는 차갑고 정적인 새벽 공과대학임. 귀엽거나 캐주얼한 분위기보다, 사람이 사라진 건물 안에 전자기기만 켜져 있는 낯선 분위기를 지향함.

2D 탑다운 시점 기준의 스타일 방향은 다음과 같음.

- 반현실적 2D 픽토리얼 스타일을 사용함.
- 오브젝트는 실제 공과대학 물건을 알아볼 수 있을 정도로 명확하게 표현함.
- 배경은 과하게 장식하지 않고, 타일, 벽, 문, 책상, 모니터 같은 반복 구조로 공간감을 만듦.
- 플레이어가 조사 가능한 오브젝트를 구분할 수 있도록 형태와 조명 포인트를 일관되게 둠.
- UI는 화면을 장식하기보다 조사와 퍼즐 입력을 차분하게 지원함.

고퀄리티 느낌을 위한 원칙은 다음과 같음.

- 모든 배경과 오브젝트는 같은 해상도 기준과 같은 선명도 기준을 따름.
- 도형, 텍스처, UI, 이펙트가 서로 다른 스타일로 섞이지 않게 함.
- 화면의 주 색상은 제한하고, 상호작용 포인트에만 보조 색을 사용함.
- 조명과 그림자를 통해 단순한 2D 화면에 깊이를 부여함.
- 임시 도형 단계에서도 색상, 크기, 배치 기준을 실제 아트 방향과 맞춤.

## 3. 색감 규칙

메인 색상은 새벽 공과대학의 차가운 분위기를 유지하는 색으로 제한함.

| 구분 | 색감 | 사용 위치 |
| --- | --- | --- |
| 메인 | 청회색 | 벽, 바닥 그림자, UI 보조 텍스트 |
| 메인 | 짙은 네이비 | 어두운 복도, 배경 음영, 엔딩 화면 |
| 메인 | 무채색 | 타일, 철제 문, 책상, 사물함 |
| 메인 | 차가운 형광등 흰빛 | 천장 조명, 조사 가능 영역 강조 |
| 포인트 | 모니터 청록빛 | 컴퓨터, 서버실 장비, 보안 패널 |
| 포인트 | 경고/비상등 붉은빛 | 잠금 오류, 제한 구역, 엔딩 직전 경고 |
| 포인트 | 최소한의 노란 조명 | 과사무실 스탠드, 낡은 복도등 |

금지 또는 제한할 색감은 다음과 같음.

- 지나치게 밝은 원색
- 귀여운 파스텔톤
- 통일감 없는 과한 색상 혼합
- 따뜻한 카페풍 갈색 팔레트
- 장면마다 전혀 다른 색조를 사용하는 방식

색감은 플레이어가 공간의 기능을 직관적으로 구분하도록 돕되, 전체 화면은 하나의 밤 시간대 안에 묶여야 함.

## 4. 질감과 오브젝트 스타일

질감은 오래된 공공 교육기관의 무광 재질과 전자기기의 차가운 표면을 중심으로 설계함.

주요 질감 기준은 다음과 같음.

- 낡은 학교 타일 바닥: 반복 패턴, 약한 오염, 낮은 반사감
- 무광 벽면: 밝은 회색 또는 청회색, 오래된 게시물 자국
- 철제 문: 짙은 회색, 작은 유리창, 전자 잠금 장치
- 공공기관식 사물함: 같은 크기 반복, 번호 스티커, 약한 스크래치
- 오래된 컴퓨터와 모니터: 두꺼운 베젤, 청록빛 화면, 팬 소음과 연결
- 강의실 책상과 의자: 반복 배치, 사용감 있는 상판
- 과사무실 서류함: 회색 철제 캐비닛, 라벨, 잠금 장치
- 프린터와 전화기: 행정 공간의 단서 제공 오브젝트
- 공지판: 포스터, 시간표, 출입 안내문, 일부 찢어진 종이
- 서버실 장비: 검은 랙, 점멸 LED, 차가운 청색 조명

모든 오브젝트는 같은 스타일과 해상도 기준을 따름. 조사 가능한 오브젝트는 살짝 밝은 테두리, 조명 반사, 또는 작은 UI 힌트로만 강조함.

## 5. 조명과 분위기

시간대는 새벽 3시임. 플레이어가 느껴야 하는 분위기는 공포 추격보다 미스터리와 긴장감에 가까움.

조명 규칙은 다음과 같음.

- 꺼진 건물 안 일부 구역에만 형광등이 켜져 있음.
- 형광등은 차가운 흰빛이며, 오래된 구역에서는 약하게 깜빡임.
- 컴퓨터와 서버 장비는 청록빛을 내며 주변 바닥에 약한 색을 남김.
- 복도 끝은 완전히 밝히지 않고, 이동 목표만 보이게 함.
- 과사무실은 노란 스탠드 조명을 제한적으로 사용해 행정 공간임을 구분함.
- 서버실은 가장 차갑고 기계적인 청색 조명으로 마무리함.

이벤트성 조명은 플레이어를 놀라게 하기보다, 특정 오브젝트 활성화 또는 공간 전환을 알려 주는 신호로 사용함.

## 6. UI 스타일

UI는 검은 반투명 박스와 흰색/청회색 텍스트를 기본으로 함. 포인트 색은 청록색만 최소한으로 사용함.

UI 구성 원칙은 다음과 같음.

- 조사 텍스트 박스는 하단 또는 중앙 하단에 배치함.
- 텍스트는 짧고 명확하게 작성해 10분 플레이 흐름을 방해하지 않음.
- 비밀번호 입력 UI는 기계적 보안 패널 느낌을 사용함.
- 오답은 붉은 포인트를 짧게 표시함.
- 정답과 잠금 해제는 청록색 또는 흰색 시스템 메시지로 표시함.
- 엔딩 화면은 차가운 시스템 로그 또는 출입 기록 화면처럼 구성함.
- 모바일 대응 가능성을 고려해 버튼 크기와 입력 영역은 확장 가능한 구조로 설계함.

UI는 배경보다 눈에 띄어야 하지만, 장식이 과해져 분위기를 깨면 안 됨.

## 7. 사운드 방향

이번 작업에서는 실제 사운드 파일을 추가하지 않음. 향후 사운드 적용을 위한 방향만 정의함.

배경 앰비언스는 다음을 중심으로 설계함.

- 새벽 건물 공조음
- 먼 컴퓨터 팬 소리
- 낮은 전기음
- 멀리서 울리는 배관 또는 금속 진동
- 서버실 근처의 일정한 저주파 기계음

효과음 목록은 다음과 같음.

- 조사 효과음
- UI 열림/닫힘
- 비밀번호 숫자 입력
- 비밀번호 오답
- 비밀번호 정답
- 문 잠금 해제
- 형광등 깜빡임
- 모니터 자동 부팅
- 프린터 작동
- 전화기 짧은 신호음
- 서버실 기계음
- 안내 방송 시작음

사운드는 과장된 공포 효과보다 절제된 긴장감을 중심으로 함. 갑작스러운 큰 소리보다, 공간의 이상함을 서서히 쌓는 방향이 적합함.

## 9. 플레이타임 구조

목표 플레이타임은 약 10분임. 각 구간은 플레이어가 길을 잃지 않도록 명확한 단서와 다음 목표를 제공함.

| 시간 | 구간 | 플레이 내용 |
| --- | --- | --- |
| 0~2분 | 55516 | 시작, 조작 적응, 첫 조사 오브젝트 확인, 첫 단서 발견 |
| 2~4분 | 5층 복도와 과사무실 | 복도 이동, 조명 이벤트, 과사무실 단서 확보 |
| 4~6분 | 단서 연결과 1층 이동 | 출입 기록과 강의실 번호를 연결해 55110 이동 이유 확보 |
| 6~8분 | 55110 | 후반 퍼즐 진행, 자리 번호와 시스템 로그 조합 |
| 8~10분 | 서버실 또는 최종 공간 | 접근 패널 해제, 최종 시스템 메시지, 엔딩 전환 |

플레이어가 모든 오브젝트를 조사하지 않아도 엔딩에 도달할 수 있어야 함. 다만 선택적 조사 오브젝트는 세계관과 분위기를 강화함.

## 10. 상호작용 오브젝트 설계

전체 게임 기준 조사 가능 오브젝트는 20~30개를 목표로 함. 진행에 직접 필요한 오브젝트는 10~15개, 핵심 이벤트 트리거는 6~8개, 퍼즐은 2~3개로 제한함.

| 오브젝트 | 위치 | 역할 | 진행 중요도 |

## 11. 이벤트 설계

이벤트는 플레이어를 강제로 위협하는 방식보다 공간의 상태가 변하는 느낌을 주는 방식으로 설계함.

추천 이벤트는 다음과 같음.

| 이벤트 | 발생 조건 | 효과 | 목적 |
| --- | --- | --- | --- |
| 조명 깜빡임 | 5층 복도 첫 진입 | 복도 일부 조명이 짧게 깜빡임 | 새 공간 진입 긴장감 |
| 안내 방송 | 복도 스피커 조사 후 | 알아듣기 어려운 시스템 안내 재생 | 건물 이상 상태 암시 |
| 모니터 자동 부팅 | 55516 컴퓨터 조사 후 | 모니터 로그가 자동 표시됨 | 첫 단서 제공 |
| 복도 끝 소리 | 과사무실 단서 획득 후 | 복도 끝에서 짧은 금속음 발생 | 다음 이동 유도 |
| 오브젝트 활성화 | 프린터 조사 후 | 서류함 단서가 의미를 갖게 됨 | 단서 연결 |
| 비밀번호 단서 조합 | 55110 로그 확인 후 | 접근 패널 입력 가능 상태가 됨 | 후반 퍼즐 진행 |
| 문 잠금 해제 | 정답 입력 후 | 잠금음과 메시지 표시 | 명확한 성취감 |
| 층 이동 | 5층 조건 충족 후 | 1층 이동 구간 열림 | 구조 확장 |
| 서버실 접근 로그 표시 | 최종 패널 조사 후 | 낯선 출입 기록 표시 | 세계관 확장 |
| 엔딩 직전 시스템 메시지 | 최종 조건 충족 후 | 차가운 로그 메시지 출력 | 후속작 암시 |

핵심 이벤트는 6~8개만 직접 진행에 묶고, 나머지는 분위기 보조 이벤트로 유지함.

## 12. 퍼즐 설계 방향

퍼즐은 10분 플레이에 맞게 짧고 명확해야 함. 플레이어가 단서를 찾는 공간과 정답을 입력하는 공간이 연결되어야 하며, 단서가 너무 숨겨져 있으면 안 됨.

현재 MVP의 `0300` 비밀번호는 임시값임. 확장 버전에서는 새벽 3시, 강의실 번호, 출입 기록, 서버 점검 시간과 자연스럽게 연결되도록 조정함.

추천 퍼즐은 다음과 같음.

| 퍼즐 | 필요한 오브젝트 | 단서 | 정답 | 결과 |
| --- | --- | --- | --- | --- |
| 5층 출입문 해제 | 55516 컴퓨터, 칠판, 출석부 | 컴퓨터 로그 `03:00`, 칠판의 `5F`, 출석부의 `16` | `0316` 또는 `5516` | 5층 복도 진입 |
| 과사무실 서류함 해제 | 복도 안내판, 과사무실 전화기, 공지판 | 전화 내선 번호 일부, 공지판의 학과 코드, 안내판의 사무실 위치 | 짧은 4자리 코드 | 55110 예약표와 1층 이동 이유 획득 |
| 서버실 접근 패널 | 55110 오래된 PC, 화이트보드, 출입기록 장치 | 55110 강의실 번호, 서버 점검 시간 `03:00`, 마지막 출입 기록 | `0300` 또는 단서 기반 변형 | 서버실 접근과 엔딩 전환 |

퍼즐은 모두 UI 입력 하나로 처리할 수 있어야 함. 복잡한 인벤토리 없이 조사 상태와 전역 상태만으로 진행되도록 설계함.

## 13. 구현 우선순위

확장 구현 순서는 다음을 권장함.

1. 아트 스타일 기준 확정
2. 멀티룸 scene 구조 추가
3. 공간 이동 시스템 구현

6. 조사 텍스트와 단서 흐름 확장

현재 작업은 1번의 기준 문서화에 해당함. 실제 scene 추가와 시스템 구현은 후속 작업에서 별도 Issue/PR로 진행함.

## 14. 에셋 전략

에셋 전략은 직접 제작과 제한적 무료 에셋, 필요 시 AI 생성 이미지 보조를 혼합하는 방식이 적합함.

권장 전략은 다음과 같음.

- 핵심 배경 타일과 주요 오브젝트는 직접 제작하거나 같은 스타일의 에셋 팩으로 통일함.
- 무료 에셋은 라이선스가 명확하고 스타일이 맞는 경우에만 사용함.
- AI 생성 이미지는 참고용 콘셉트 또는 텍스처 초안으로만 사용하고, 최종 적용 시 스타일과 라이선스 출처를 명확히 정리함.
- 임시 도형은 프로토타이핑 단계에서만 사용하고, 최종 문서/포트폴리오 전에는 통일된 아트로 교체함.
- 외부 에셋 사용 시 `docs/asset-credits.md`에 에셋명, 제작자, 출처 URL, 라이선스, 사용 위치를 기록함.

향후 필요한 에셋 목록은 다음과 같음.

- 55516 강의실/실습실 배경 타일
- 5층 복도 배경 타일
- 과사무실 배경 타일
- 계단 또는 층 이동 구간 배경
- 55110 강의실/실습실 배경
- 로비와 출입 게이트 배경
- 서버실 배경과 서버랙 오브젝트
- 컴퓨터, 모니터, 책상, 의자, 사물함, 문, 프로젝터, 프린터, 전화기, 공지판, 안내판, CCTV, 자판기, 서버랙 오브젝트
- 조사 UI, 비밀번호 UI, 시스템 메시지 UI 스킨
- 앰비언스와 효과음 파일

현재 작업에서는 에셋을 추가하지 않음.

## 15. 범위 통제

절대 추가하지 말아야 할 것은 다음과 같음.

- 전투
- 적 AI 추격
- 복잡한 인벤토리
- 세이브/로드
- 대형 오픈월드
- 장시간 대화 시스템
- 랜덤 생성 맵
- 복잡한 분기 엔딩

추가해도 되는 것은 다음과 같음.

- 짧은 이벤트
- 조사문구
- 공간 이동
- 간단한 퍼즐
- 분위기 사운드
- 짧은 엔딩 연출
- 최소한의 단서 상태 관리
- 간단한 시스템 로그 UI

범위 통제의 핵심은 10분 안에 끝나는 완성도 있는 경험임. 공간 수와 오브젝트 수를 늘리더라도 플레이어의 목표가 흐려지면 안 됨.

## 16. 향후 Unreal 후속작 연결

Godot 2D 작품은 세계관 프롤로그 역할을 함. 플레이어는 새벽 3시 공과대학에서 발생한 이상한 출입 기록과 서버실 로그의 일부만 확인하고 끝남.

Unreal 후속작은 같은 공과대학을 1인칭 공포/미스터리 탐험으로 확장할 수 있음. 후속작 연결을 위해 2D 작품에는 다음 상징을 남김.

- 공과대학 건물
- 55516과 55110 강의실 번호
- 새벽 3시
- 서버실 접근 기록
- 알 수 없는 사용자명
- CCTV와 출입 게이트
- 시스템 로그 형식의 엔딩 메시지

2D 작품은 사건의 전모를 설명하지 않고, 후속작에서 더 큰 사건을 탐색할 수 있는 질문을 남기는 방식이 적합함.
