# 비주얼 에셋 파이프라인 계획

## 1. 목적

이 문서는 임시 도형 기반 멀티룸 게임을 고퀄리티 2D 비주얼로 전환하기 위한 준비 문서임.

실제 이미지, 사운드, 폰트 에셋을 추가하기 전에 스타일 기준과 파일 구조를 먼저 고정하는 것이 목적임. 이후 비주얼 패스와 사운드 패스는 이 문서를 기준으로 작은 PR 단위로 적용함.

## 2. 비주얼 기준

전체 비주얼은 차갑고 정적인 새벽 공과대학 분위기를 기준으로 함.

- 메인 색상은 청회색, 짙은 네이비, 무채색, 차가운 형광등 흰빛을 사용함.
- 포인트 색상은 모니터 청록빛과 비상등 붉은빛을 제한적으로 사용함.
- 귀여운 픽셀풍, 과한 원색, 파스텔톤, 장면마다 다른 색조는 제한함.
- 배경, 오브젝트, UI는 같은 해상도, 질감, 톤을 유지함.
- 조사 가능 오브젝트는 과한 하이라이트보다 조명 반사, 테두리, 작은 색 차이로 구분함.
- 임시 도형을 실제 에셋으로 바꿀 때도 기존 충돌 영역과 상호작용 위치는 유지함.

## 3. 에셋 폴더 구조 제안

향후 에셋 추가 시 다음 구조를 기준으로 정리함.

```text
assets/
  art/
    characters/
    rooms/
    objects/
    ui/
    effects/
  audio/
    bgm/
    ambience/
    sfx/
  fonts/
```

| 폴더 | 용도 |
| --- | --- |
| `assets/art/characters/` | Player 등 캐릭터 스프라이트, 이동 방향별 이미지 |
| `assets/art/rooms/` | room 배경, 바닥 타일, 벽, 큰 구조물, 공간별 배경 이미지 |
| `assets/art/objects/` | 조사 오브젝트, 장식 오브젝트, 문, 장비, 가구 이미지 |
| `assets/art/ui/` | DialogueBox, PasswordInput, 버튼, 시스템 패널, 엔딩 UI |
| `assets/art/effects/` | 조명 깜빡임, 모니터 빛, 경고등, 전환 효과용 이미지 |
| `assets/audio/bgm/` | 음악이 필요할 경우 배경 음악 보관 |
| `assets/audio/ambience/` | 공조음, 전기음, 서버실 기계음 같은 반복 배경음 |
| `assets/audio/sfx/` | 조사, UI, 비밀번호, 문, 전환, 이벤트 효과음 |
| `assets/fonts/` | UI와 문서화된 게임 내 텍스트에 사용할 폰트 |

현재 작업에서는 위 폴더에 실제 에셋을 추가하지 않음.

## 8. 에셋 적용 우선순위

고퀄리티 체감이 큰 순서대로 적용함.

1. UI 패널과 폰트
2. 방 배경, 바닥, 벽
3. 주요 조사 오브젝트
4. 조명과 색감
5. 사운드
6. 효과와 전환 연출
7. 세부 장식 오브젝트

초기 비주얼 패스는 전체 공간을 한 번에 완성하려 하지 않고, UI와 Room55516부터 적용함. 이후 공용 오브젝트와 멀티룸 배경으로 확장함.

## 9. 에셋 제작/수급 전략

| 방식 | 장점 | 단점 | 추천도 |
| --- | --- | --- | --- |
| 직접 제작 | 스타일 통일이 가장 쉬움, 포트폴리오 설명이 명확함 | 시간이 오래 걸림 | 높음 |
| 무료 CC0 에셋 사용 | 빠르게 적용 가능, 라이선스 부담이 적음 | 스타일이 섞이기 쉬움 | 중간 |
| AI 생성 이미지 사용 | 콘셉트 시안과 텍스처 초안에 빠름 | 일관성, 저작권, 수정 비용 관리 필요 | 보조 |
| 임시 도형 유지 후 점진 교체 | 기존 구현 안정성 유지 | 고퀄리티 체감은 늦게 올라감 | 높음 |

현재 프로젝트에는 `직접 제작 + 임시 도형 점진 교체 + 제한적 CC0 보조` 전략을 추천함.

AI 생성 이미지는 최종 에셋으로 바로 넣기보다 콘셉트 시안, 질감 참고, 색감 기준을 잡는 보조 수단으로 제한함. 실제 적용 시 생성 도구, 프롬프트 목적, 사용 위치를 기록함.

## 10. 라이선스/출처 관리 규칙

- 외부 에셋은 반드시 `docs/asset-credits.md`에 기록함.
- 기록 항목은 asset name, creator, source URL, license, usage location임.
- 출처 불명 에셋은 사용하지 않음.
- 라이선스가 상업적 사용 또는 재배포에 불명확하면 사용하지 않음.
- AI 생성 이미지 사용 시 생성 도구와 사용 범위를 기록함.
- 무료 에셋을 편집해 사용한 경우 원본 출처와 편집 여부를 함께 기록함.
- 폰트는 게임 빌드에 포함 가능한 라이선스인지 별도 확인함.

## 11. Godot 적용 방식

비주얼 적용은 기존 동작을 보존하는 방향으로 진행함.

- 기존 ColorRect/Polygon2D 기반 임시 도형을 Sprite2D 또는 TextureRect 기반 에셋으로 교체함.
- scene 구조를 크게 흔들지 않고 `Visual` 노드 중심으로 교체함.
- CollisionShape2D는 이미지와 별도로 유지함.
- Area2D, object_id, state_key, TransitionZone 로직은 유지함.
- 오브젝트 크기가 바뀌어도 interaction/collision 기준은 먼저 유지하고, QA 단계에서만 조정함.
- room 배경은 우선 큰 배경 이미지 또는 타일 조합으로 넣고, 벽 충돌은 기존 StaticBody2D를 유지함.

## 13. Room55516 이후 비주얼 품질 기준

현재 Godot 기본 도형 기반 비주얼은 최종 에셋이 아니라 블록아웃임. Room55516 비주얼 패스 1차/2차는 레이아웃, 충돌, 오브젝트 위치, 상호작용 흐름을 확인하는 데 의미가 있지만, 고퀄리티 공개용 화면 기준으로는 질감과 실루엣이 부족함.

고퀄리티 목표를 위해서는 실제 2D 에셋 기반 전환이 필요함. 특히 Player sprite, Room55516 floor/wall, computer/blackboard/desk/locker/door, 조명/그림자 overlay를 먼저 적용해야 함.

구체적인 품질 진단, 에셋 목록, 적용 순서, 야간 순찰자/NPC 이벤트 대비 기준은 [`docs/visual-quality-roadmap.md`](visual-quality-roadmap.md)를 기준으로 관리함.

## 14. Room55516 에셋 기반 적용 1차 메모

Room55516 에셋 기반 적용 1차에서는 `assets/art/characters/player/`, `assets/art/rooms/room55516/`, `assets/art/objects/room55516/`, `assets/art/effects/`에 프로젝트 내부 제작 SVG 초안을 추가함.

적용 방식은 기존 CollisionShape2D와 Area2D를 유지하고, scene의 시각 요소를 Sprite2D 기반 Texture2D로 보강하는 방식임. 이 방식은 기존 상호작용 로직을 보존하면서 Player와 주요 오브젝트가 단순 도형으로 보이는 문제를 줄이는 데 목적이 있음.

Room55516 에셋 QA polish 단계에서는 기존 SVG를 유지하되 Player, floor, light, monitor glow, 주요 오브젝트의 stroke, shadow, highlight, scene scale을 조정함. Godot이 생성한 실제 게임 에셋용 `.svg.import` sidecar는 해당 SVG와 함께 추적 대상으로 판단함.

Room55516 비주얼 오버홀 1차에서는 Player sprite를 `down`, `up`, `left`, `right` 방향별 SVG로 분리하고, 이동 방향에 따라 texture를 교체하는 방식으로 적용함. 주요 오브젝트 SVG는 윗면/측면/전면, 그림자, 하이라이트를 보강해 단순 사각형 느낌을 줄이는 기준선으로 사용함.

이후 Room55516 탑뷰 일관성 정리에서는 오브젝트별 카메라 시점이 섞이지 않도록 `같은 타일 그리드 위에 놓인 탑뷰 오브젝트` 기준을 우선함. scene 내부의 오래된 placeholder 도형은 가능한 한 숨기고, 실제 화면 표현은 SVG 에셋과 일관된 scale/배치 규칙으로 관리함.
